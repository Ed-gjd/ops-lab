# SSH 学习计划（小白→专家）

> 主路线独立文档。与《运维学习计划.md》的「SSH 七级穿插位置」（§五）配合：本计划按 SSH 自身逻辑由浅入深拆全，运维计划按业务能力穿插验证，交叉学习。
> 版本：2026-08-12

---

## 一、先立观念（大白话）

1. **SSH 是「远程进机器」的唯一事实标准**。云服务器、运维、开发部署、GitHub 推送全走它。学会 SSH ≈ 学会"人和机器之间的安全通道"，是一切远程操作的地基。
2. **SSH 只干三件事**：
   - **加密**：内容谁也看不到（防偷听）
   - **认证**：证明你是你、机器是那台机器（防冒充）
   - **通道**：把任意端口/服务的数据顺着加密管道搬（隧道/跳板/Agent 全在这）
   - 所有高级玩法都是这三件事的组合。
3. **学的不是背命令，是"会折腾 + 会定位"**：每课动手、每课验收、命令全明文、坏了能退（快照）。总纲见《学习方法论与协作协议.md》。
4. **七级心智地图**（本计划按此展开）：
   - L1 能用 → L2 密钥/config → L3 隧道/跳板/加固 → L4 协议/自动化 → L5 PKI/架构 → L6 攻防/前沿 → L7 信任模型
5. **本计划核心重点：反向隧道（内网穿透）** —— 已在你真实环境跑通过一轮（skill `ssh-reverse-tunnel`），阶段 3 围绕它讲透，并升级到"工程化 + 验收闭环 + 故障演练"。
6. **以 Ubuntu 环境为主**：全计划在 Ubuntu VM（练习机 .133 + node1/2/3）里跑通。Windows 只承担两个跑不掉的角色：**SSH 客户端**（你从它连进去）和**反向隧道的"真实局域网可达端点"**（所有 Ubuntu VM 都在 VMware NAT 后面，手机能访问的只有 Windows）。除此之外一律在 Ubuntu 内完成。
7. **支撑两条真实工作流**：① **远程开发**——VS Code Remote-SSH 直接在 VM 上写/跑/调代码，开发服务器端口搬回本机预览；② **部署**——rsync/Git + systemd + CI/CD 把代码可靠送上服务器。SSH 是这两条工作流的地基，在对应阶段实战里落实。

## 二、通用工具链与方法（所有阶段共用）

### 工具链

| 用途 | 工具 | 说明 |
|---|---|---|
| SSH 客户端 | Windows 自带 OpenSSH + Windows Terminal | 免费够用，练通用 `ssh` 命令 |
| 远程开发 IDE | VS Code + Remote-SSH 插件（阶段2 装） | 远程编辑/运行/调试 VM 代码，底层就是一条 ssh 通道 |

| 查证 | `man ssh` / `man ssh_config` / `man sshd_config` | 第一手资料，新概念先查 man |

**环境定位（Ubuntu 为主）**：所有阶段的服务端 / 隧道 / 加固 / 自动化 / CA 都在 Ubuntu VM 上做；Windows 仅作为 SSH 客户端出现。唯一例外是阶段3 反向隧道——手机必须访问真实局域网，所以那头的 sshd 落在 Windows（全实验室只有它在真实局域网）。另有纯 Ubuntu 变体演示，见阶段3 课5。

### 方法（照方法论，最高优先无例外）

- **命令全明文**：每个要执行的命令先在对话完整写出（含参数）→ 再执行 → 输出全贴。
- **先方案后执行**：破坏性/有风险操作先给方案（含回滚）确认后动手。
- **每课验收**：有可测通过标准，过不了不进下一课。
- **不重复**：已会内容直接跳（见「三、起点评估」）。
- **vibe 循环**：直接讲 → 做 → 执行后解释 → 考问判断（"这条哪步能省？为什么不用 X？"）。**不做"执行前让用户猜结果"环节**（用户明确"不猜"）。

## 四、学习路线（7 阶段）

### 阶段 1：SSH 是什么 + 第一次登录（4 课）⭐入门
（L1；大部分已会，作快速复核 + 补 config 短板）
- 课1：SSH 三件事（加密/认证/通道）+ 端口 22 + 连接流程（客户端→服务器→host key 验证→认证→会话）
- 课2：第一次登录 + `known_hosts` + host key 指纹验证（为什么第一次要确认指纹——TOFU 首次信任）
- 课3：密钥认证全通：`ssh-keygen -t ed25519`、`ssh-copy-id`、`~/.ssh/authorized_keys`、权限坑（700/600）
- 课4：`~/.ssh/config`：别名、端口、用户、多主机、通配符
- **阶段验收**：用 config 免密登录 VM；讲清 host key 验证在防什么

### 阶段 2：日常操作与远程开发（6 课）
（L1-L2；从"能连"到"会用 SSH 干活"，支撑远程开发工作流）
- 课1：`scp` / `sftp` / `rsync` 传文件（三者适用场景对比 + 断点续传等坑）
- 课2：远程执行命令、管道、for 循环批量、`$(ssh ...)` 取返回值
- 课3：`tmux` + SSH：长任务挂断不丢（命令放 tmux，断线重连继续）
- 课4：`ControlMaster` 连接复用 + 批量并行（`xargs -P` 多 VM 并行）
- 课5：**远程开发：VS Code Remote-SSH**——在 VM 上远端编辑/运行/断点调试（跑真实 Python 脚本）；理解底层就是一条 ssh 通道，复用已学的密钥/config
- 课6：**开发服务器端口预览**：`ssh -N -L 0.0.0.0:8081:127.0.0.1:5000 user@vm` 把 VM 上的 flask/jupyter 端口搬回本机浏览器调试
- **阶段验收**：VS Code 远程改 VM 上的脚本并运行；一条命令同步目录到 3 台 VM 校验 md5；长任务断线后 tmux 恢复

### 阶段 3：隧道 / 跳板 / 内网穿透（6 课 + 综合实战）⭐真正的分水岭
（L3；**含本会话反向隧道项目，本计划核心**）
- 课1：端口转发三件套 `-L` / `-R` / `-D`：**监听口开在哪头** + 目标地址以哪台机器视角解析（亲手画/讲一遍，这是后面所有坑的源头）
- 课2：正向隧道 `-L`：访问内网里"连不进来"但本机能触达的服务（`ssh -N -L 0.0.0.0:8080:127.0.0.1:8000 user@vm`）
- 课3：跳板机：`ProxyJump` / `ProxyCommand` 多跳（本机→node1→node3）
- 课4：动态转发 `-D`：SOCKS 代理（本机当代理出口）
- 课5：**反向隧道 `-R`：内网穿透（本会话项目）**。场景：VM 在 NAT 后连不进来，手机要访问 VM 服务。完整链路：VM 主动拨出 → Windows sshd（`GatewayPorts=yes`，绑 `0.0.0.0`）→ 手机访问 `http://<Windows局域网IP>:8080`。含：
  - Windows 侧：装 OpenSSH Server、`GatewayPorts yes`、防火墙放行 22/8080
  - VM 侧：专用密钥 `id_ed25519_tun`、**管理员公钥放 `C:\ProgramData\ssh\administrators_authorized_keys`（不是 `~/.ssh/authorized_keys`）**、`-R 0.0.0.0:8080:127.0.0.1:8000`
  - 验证顺序：`curl 127.0.0.1:8080` → `netstat` 见 `0.0.0.0:8080 LISTENING` → `curl <Windows局域网IP>:8080` → **手机访问**
  - 详细 playbook：`C:\Users\<USER>\cc\.claude\skills\ssh-reverse-tunnel\ssh-r-SKILL.md`
  - 纯 Ubuntu 变体（可选）：在实验网段内用 node3 当 sshd 服务端、任意 VM 当被访问端，先纯 Ubuntu 演示 `-R` 原理与数据流；手机访问仍走 Windows 端点（真实局域网唯一入口）
- 课6：反向隧道工程化：自动重连 `~/.tunnel/autoreconnect.sh`（`while true` + `ServerAliveInterval`）+ `@reboot` cron 开机自启 + 多服务/多端口转发 + 排错清单（`pkill -f` 自杀坑、`GatewayPorts` 改完没重启、AP 隔离…）+ **对比现代内网穿透替代**（Cloudflare Tunnel / frp / ngrok，看懂本质是同一件事）
- **综合实战（本轮要做的）**：修通断点（VM 起 `python3 -m http.server 8000`）→ 全链路验收（含手机）→ **故障演练**：`pkill -f '[i]d_ed25519_tun'` 杀隧道，8 秒内自动重连，服务仍通 → 出一份"隧道项目小结"
- **阶段验收**：手机能访问 VM 服务；一句话讲清 `-L / -R / -D` 各自监听口开在哪、目标按谁的视角解析

### 阶段 4：服务端管理与加固（5 课）⭐安全分水岭
（L3-L4；从"用"到"管/守"）
- 课1：`sshd_config` 全解：端口、监听地址、`PermitRootLogin`、`ClientAliveInterval`、`MaxSessions`、`AllowUsers/AllowGroups`、`PasswordAuthentication`
- 课2：加固实战：禁 root 登录、禁密码登录、`fail2ban` 防爆破、UFW 只放行必要端口、改端口（争议点：安全 vs 麻烦）
- 课3：双因子：密钥 + 口令（`AuthenticationMethods`）、PAM `google-authenticator`
- 课4：日志与审计：`journalctl -u ssh`、`/var/log/auth.log`、`last/lastb`、连接监控（谁在连、从哪来）
- 课5：sshd 排错与恢复：`sshd -t` 先验配置、**双会话保底**、开防火墙先放行 22
- **阶段验收**：给自己的 VM 出一份加固清单并逐条落实，用另一个终端证明加固生效且自己仍能正常登录

### 阶段 5：协议原理与自动化（7 课）
（L4；从"会用"到"懂为什么"，支撑部署工作流）
- 课1：协议三层架构（传输层/认证层/连接层，RFC 4251-4253）+ 用 `ssh -vvv` 读一次真实握手
- 课2：密码学地基：对称/非对称/DH 密钥交换/哈希/签名/完美前向保密（讲清 ssh 握手即可，不深入数学）
- 课3：算法与指纹：`ssh-keygen -l -f` 看指纹、`known_hosts` 哈希化、host key 轮换
- 课4：`Agent Forwarding` 原理与**风险**（为什么默认关）、`ControlMaster` 深挖、`BatchMode` 自动化
- 课5：Ansible 与 SSH：连接机制、inventory、并行、幂等（用 .133 控 node1/2 实测）
- 课6：**部署实战**：rsync/Git + systemd 把真实应用（flask/静态站）送上 VM——代码同步、服务托管、开机自启、日志、回滚
- 课7：**CI/CD 自动化部署**：GitHub Actions 经 SSH 部署；NAT 后的 VM 用**自托管 runner**（免开公网口）；发布=一条流水线
- **阶段验收**：贴一条 `ssh -vvv` 完整输出逐层讲清；跑通一次"改代码→自动部署→访问生效"闭环；能说清 Agent Forwarding 为什么危险

### 阶段 6：PKI 与大规模架构（5 课）→ 半专家
（L5）
- 课1：证书 vs 裸密钥：为什么大规模要用 CA（集中签发/吊销/短时效）
- 课2：**SSH CA 实战**：`ssh-keygen` 做 CA，给主机/用户签发证书，`TrustedUserCAKeys`、`@cert-authority`、吊销
- 课3：堡垒机/跳板架构：集中入口、审计、会话录屏（概念 + 对比）
- 课4：云厂商 SSH 生态对比（**每课固定尾部**）：阿里云/腾讯云 密钥对管理、控制台 VNC、`Session Manager`/`SSM`、云堡垒机（命令对比用代码块逐条列，不用表格）
- 课5：大规模治理：inventory 维护、批量生成 `~/.ssh/config`、密钥/凭据管理（Hashicorp Vault 概念）
- **阶段验收**：自己搭一个 mini SSH CA，签发主机证书：一台认证成功、一台吊销后失败

### 阶段 7：攻防、前沿与信任模型（5 课 + 综合项目）
（L6-L7）
- 课1：攻击面与攻防：中间人、host key 劫持、SSH 隧道滥用（反弹 shell/代理跳板）、历史 CVE 回顾
- 课2：**近期版本与前沿**：`ssh -V` 看版本、`ssh -Q kex` 列算法；混合后量子 KEX `mlkem768x25519-sha256` 强制/回退验证；FIDO2 安全密钥 `sk-ed25519` 上手
- 课3：信任模型深究：TOFU 首次信任 vs 证书固定 vs CA 信任；供应链信任（从哪拿的二进制/密钥）
- 课4：协议生态对比：SSH vs VPN/WireGuard、SSH over HTTPS、云 Session Manager（按需演示）
- 课5：研究向（了解即可）：读 RFC 4251-4256 / OpenSSH 源码，写一个 mini SSH 客户端（可选）
- **综合项目**：写一份《企业级 SSH 安全架构设计》方案（分层：网络→主机→认证→审计→自动化→治理），并对实验室做一次攻防演练
- **阶段验收**：方案文档 + 演练总结（问题→原因→解决）

## 六、协作协议适配（SSH 特有）

1. **命令全明文无例外**：SSH 领域最容易犯"ssh 包裹缩略"——只给缩略版、实际跑长命令（被点过名）。任何远程操作命令先完整写出再执行。
2. **改 sshd 配置铁律**：改前先 `sshd -t` 验证 → 再重启；**全程保持两个会话**（一个改、一个保底）；改坏立刻恢复。开防火墙先放行 22。
3. **危险操作边界（必须先给方案含回滚）**：禁 root、禁密码登录、清防火墙规则、全局改配置、杀进程——一次问清不绕。
4. **3 次升级机制**：失败 1 次自解决；2 次停止猜，贴"报错原文 + 相关配置 + 环境状态"三件套；3 次降级半自动（给命令用户手动跑）。
5. **要密码提前说**：三方案（要密码 / 配免密 / 用户手动跑）。
6. **vibe 循环**：直接讲 → 做 → 执行后解释 → 考问判断。不搞"执行前让用户猜"。
7. **每课固定尾部「跨厂商对比」**：重点阿里云 + 腾讯云（概念对照 + 命令对比 + 差异坑）；命令对比用**代码块逐条列出**（表格会被终端截短）。

## 八、近期版本与前沿技术速览（2026-08 调研，保持最新）

> 方法论要求"保持最新"：涉及行业方向先查当前成熟实践与最新技术，不凭旧知识硬套。**每阶段开课前查一次官方 Release Notes**。下面分四层：版本锚点 / 应在主干上手的前沿 / 持续关注的方向 / 了解即可的替代。

**① 版本锚点（当前）**
- 本机环境：Ubuntu 24.04 LTS（自带 OpenSSH 9.6p1）；最新 LTS 26.04 于 2026-04 发布，新实验可在它或上游 OpenSSH 上做
- 上游：OpenSSH 9.9+ 默认启用**混合后量子密钥交换**；10.x 系列持续推进 PQ 默认化与旧算法淘汰
- 查证命令：`ssh -V`（本机版本）、`ssh -Q kex`（列出可用密钥交换算法）、`man ssh_config`（最新参数）

**② 应在主干上手的前沿（动手）**
- **后量子密码（PQ）**：混合 KEX `mlkem768x25519-sha256`（NIST ML-KEM），用 `ssh -o KexAlgorithms=...` 强制/回退验证；了解迁移矩阵与存量兼容
- **FIDO2 / 安全密钥**：`ssh-keygen -t sk-ed25519 -O resident`、`verify-required`；硬件密钥当主机/用户密钥（阶段7 上手）
- **SSH CA 用户证书**：签发/吊销/短时效（阶段6 完整实战）
- `ProxyJump` 多跳、`ControlPersist` 连接复用：已是日常标配

**③ 持续关注的方向**
- PQ 迁移路径：算法兼容矩阵、废弃算法时间表、合规（FIPS/DNSSEC）要求
- 移动/弱网：`mosh`（UDP、漫游）vs SSH；云端会话管理（AWS SSM / 阿里云 / 腾讯云，免开 22）
- 内网穿透现代替代：Cloudflare Tunnel / frp / ngrok——阶段3 学完 SSH -R 后对比，看懂本质是同一件事

**④ 了解即可（不深挖）**
- 企业身份接入：SSSD / LDAP / AD Kerberos；passkey / WebAuthn 与 SSH 的交叉
- SSH over HTTPS（443 端口逃生）；SSH over QUIC（实验）
- RFC 4251 系列及后续扩展

**⑤ 在各阶段的落实**

| 阶段 | 前沿落点 |
|---|---|
| 3 | 反向隧道 vs Cloudflare Tunnel / frp / ngrok 对比（了解） |
| 5 | `ssh -V` / `ssh -Q kex` / 算法矩阵（动手） |
| 6 | SSH CA + 云会话管理（动手） |
| 7 | PQ 迁移 + FIDO2 + 信任模型（动手/方案） |
