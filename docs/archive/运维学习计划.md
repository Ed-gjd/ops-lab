# 运维学习实践计划（小白 → 专家）

> **环境**：Windows 11 本机（AMD Ryzen 7 5700U / 8核16线程 / 16G 内存 / D盘剩约147G）+ Ubuntu 24.04 VM（4G/2核，NAT 网络）
> **协作模式**：Claude 当助手（vibe 工作法）。**遇问题先评估、提前说、不硬干卡死。**
> 本文档整合：学习路线（主线七阶段 + 支撑两阶段）+ 网络问题排查预案 + 防兜圈协议 + 密码约定 + 代理（PandaFan）操作协议 + 2026 前沿。

## 一、理性基调（先说清预期）

- **运维不是背命令，是"会系统地折腾 + 会快速定位问题"**。所有知识都长在动手上。
- 本机硬件足够撑到"进阶期"。单台 4G VM 练基础够；玩 k8s 和双网段时才扩成多台，按需开机（16G 内存扛不住 8 台全开）。
- 这条路有 **3 个分水岭**：Shell 自动化 → Ansible+监控 → 容器编排。过得去才叫"工程师"，过不去就是"搬砖的"。
- 时间预期（每天 1–2 小时）：小白到"能独立管 5 台机器"约 **3–6 个月**；到"专家"是 **1–2 年以上**，专家是靠事故和复盘喂出来的。
- **2026 时代定位**：AI 辅助运维（Agentic SRE）已是行业方向（Gartner 预测 2029 年 85% 企业用 AI SRE 工具）。本计划从第一天就用 Claude 练"**人定护栏、AI 执行**"——这既是学习方法，本身也是未来的职业技能。详见第十二节。

## 二、Claude 协作协议（vibe 工作法）——整个计划的操作系统

### 2.1 VIBE 四步循环

1. **V（Voice）用大白话下指令**——说目的，不说术语。
   - 好的：*"帮我把 nginx 设成开机自启，用最土的办法，先别教 systemctl。"*
   - 坏的：*"edit /etc/rc.local 加一行 service nginx start"*
2. **I（Iterate）让它执行并反馈**——Claude 跑命令，把输出原样贴回，并告诉"发生了什么、结果对不对、为什么"。
3. **B（Backtrace）出错就进调试循环**——报错看不懂就贴原文：*"它报 permission denied，我不懂，你先解释原因再给修复。"* 先解释再动手。
4. **E（Explain）每个动作都要解释**——每个命令讲清"干嘛的、为什么这么干、有什么坑"，从"会复制"变"会判断"。

### 2.2 三个 vibe 指令模板

| 类型 | 模板 |
|---|---|
| 执行型 | 「帮我 [目标]，[约束]，你负责解释每一步」 |
| 教学型 | 「用大白话讲 [概念]，举一个我们虚拟机里的例子」 |
| 调试型 | 「[贴报错原文]，我做了 [什么事]，帮我看是哪层的问题，先解释再修」 |

### 2.3 铁律（重要约定）

1. **先方案后执行**：破坏性操作（删、改配置、重装）必须先给方案，确认后才动手。
2. **快照兜底**：动配置前先打 VMware 快照/克隆，出问题一键回退。
3. **不背不抄**：命令可以抄，但必须复述得出来；解释不了的命令下次不用。
4. **要密码提前说**（2026-08-01 用户补充）：任何操作需要密码时，**不闷头卡死、不反复试**，提前说明"这步要密码"，给出三种方案：向用户要密码 / 配免密绕过 / 请用户手动执行。
5. **动手前先评估**（2026-08-01 用户强调）：开始前评估风险，需要用户确认的点**提前说**，确认后才开始。**不硬干卡死**——遇到问题先报告再行动。

## 三、环境规划：一台 VM 玩出多台的效果

| 阶段 | 用什么环境 | 为什么 |
|---|---|---|
| 基础 ~ Shell | 单台 Ubuntu24 + 本机 Windows | 一台够练基础；Windows 侧练 SSH 客户端 |
| Ansible 分水岭 | 克隆 2–3 台（控制端 + 被管端） | Ansible 至少"一控多管"才叫自动化 |
| 网络/网关 | 加一台双网卡 node1 做 NAT/防火墙 | 单台玩不出"多网段互通" |
| 容器云原生 | 克隆 3 台跑 **k3s** 轻量集群 | 4G 单机跑不动正经 k8s |
| 高可用/监控 | 按需全拓扑（常开 5 台 ≈ 8G） | 模拟生产得多台才像样 |

**双网段 8 台规划**（外网段 VMnet8 + 内网段 VMnet2，node1 双网卡做网关/防火墙/NAT）：
- 常开 5 台：node1 网关 1G / node2 nginx-LB 1G / node3 Ansible+Prometheus 2G / node4 web 2G / node5 MySQL 2G（合计 8G）
- 按需 3 台：node6 Redis 1G / node7-8 k3s 各 2G
- **克隆后必改三件**：主机名、重新生成 SSH host key（`rm /etc/ssh/ssh_host_* && ssh-keygen -A`）、固定 IP

> 内存提醒：16G 是硬顶，开哪几台按需来。

### 3.1 实验室管理：破坏准备与复用（重点）

**分层结构——把"能拆的"和"要留的"分开：**
| 层 | 是什么 | 规则 |
|---|---|---|
| 模板机 | 干净基线 Ubuntu24，只打补丁 + 装基础工具 | **永远不被实验破坏**；所有实验机从它克隆 |
| 工作机 | 日常练习场 | 坏了回退、丢了再克隆 |
| 实验机 | 临时拿来拆的（装坏系统/删库/烧防火墙） | 用完即弃，释放 D 盘 |

**快照三级策略（破坏前的准备）：**
- **L0 基线快照**：模板刚装好、基础配置完成时打，`baseline-<日期>`，最后防线。
- **L1 阶段快照**：每进一个学习阶段前打，`stageN-start`，坏了回这。
- **L2 操作前快照**：每次破坏性操作前打，`before-<操作名>`，验证完即删（防快照堆满 D 盘）。
- **回退规则**：丢 L2 → 回 L1；丢 L1 → 回 L0；全丢 → 重新克隆重做基础。

**破坏性实验前的 5 项准备（写死，别省）：**
1. 打 L2 快照。
2. 关键配置/数据备份到本机 `D:\backup\<日期>\`。
3. 确认恢复路径：VMware 控制台能进、知道恢复模式怎么进（否则断网后没救）。
4. 记录当前状态到笔记（`ip a`、`ss -tlnp`、要改的配置原文）。
5. 写清"这次要破坏的点 + 验证标准"——破坏要有目的，验证能恢复才算过。

**破坏的正确姿势（理念）：**
- **一次只破坏一个点**，别同时改三处（坏了不知道回哪个）。
- 破坏完**必须验证"能恢复"**。
- 坏了不心疼：回快照重来，这是最便宜的学费。
- **破坏是学习资源**：第七阶段故障演练就是主动杀节点，前面练会恢复，后面才敢演。

**环境复用清单（后面还要用的，都存在 D 盘/本机，别只留在会销毁的 VM 里）：**
| 资产 | 怎么保留 |
|---|---|
| 模板机 | 只更新 + 打补丁，永远干净 |
| 网络规划表 | 一张表记死：IP / 主机名 / 角色 / 内存 |
| 实验笔记 | 每次踩坑记"问题 → 原因 → 解决" |
| 常用命令 / 脚本 | 备份到 D 盘 `D:\lab-assets\` |
| 快照 | 命名带日期和用途，跨阶段留 L1，验证完删 L2 |

**D 盘空间规则**：快照/克隆全放 D 盘；旧实验机用完即删；别让快照无限堆积（验证完删 L2）。

### 3.2 Windows 宿主侧规划（本机的"另一半"）

运维是"本机操作远程"，Windows 宿主侧必须配顺，否则第一个月全耗在工具上。

| 用途 | 推荐 | 说明 |
|---|---|---|
| SSH 客户端 | **Windows Terminal + 自带 OpenSSH** | 够用、免费、无需安装；练的是通用 ssh 命令 |
| 传文件 | `scp` / `sftp`（命令行） | 与 Linux 一致，学一次到处用 |
| 图形化工具 | VS Code Remote-SSH（进阶再装） | 熟悉后显著提速，但先不依赖 |
| 终端编码 | Windows Terminal，UTF-8 | 避免中文乱码 |

**宿主安全基线（重要）**：检测到宿主 Windows 开着 **OpenSSH 服务，监听 22 和 8080 端口（全网卡 0.0.0.0）**。如果不是你故意开的：
- 先确认意图：是你自己配的远程管理，还是误开；
- 建议限制来源 IP（防火墙只放行内网 192.168.x.x），或直接关闭服务；
- 这是宿主本身的安全暴露面，和 VM 无关，但要一起管。

## 四、学习路线（主线七阶段 + 支撑两阶段：阶段 0 / 3.5）

```
阶段0 环境体检 ─→ ①Linux地基 ─→ ②系统管理 ─→ ③网络服务 ─→ [3.5 多机搭建] ─→ ④Shell自动化 ─→ ⑤Ansible+监控 ─→ ⑥容器云原生 ─→ ⑦高可用/安全/SRE
(前置体检)   (看得懂)      (管得住)      (连得上)      (搭环境)       (会批量)      (自动化/看得见)    (会调度)       (扛得住)
```

箭头是"依赖关系"：没有前一步，下一步只能靠猜。除主线外有 2 个支撑阶段：**阶段 0**（环境体检，正式动手前把体检和前置配置一次做齐）与**阶段 3.5**（多机环境搭建，从单机过渡到多机）。每阶段**验收标准**过不了不进入下一阶段。

### 阶段 0：环境体检与前置配置（1 次，30–60 分钟）——真正的起点

在学任何东西之前，先把"地基是否结实"查一遍，把"防兜圈"的前置一次配齐。这一阶段本身就是用 Claude 走一遍"先方案后执行"的演练。

**体检清单（逐项报告，缺什么补什么）：**
| # | 检查项 | 命令/方法 | 合格标准 |
|---|---|---|---|
| 1 | VM 是否开机 | VMware 界面 / `ping <VM_IP>` | 能 ping 通 |
| 2 | SSH 是否能连 | 本机 `ssh user@<VM_IP>` | 能登进去 |
| 3 | VM 当前 IP | VM 里 `ip a` | 记下 IP，最好固定成静态 |
| 4 | 免密 sudo 是否配好 | `sudo -n true && echo OK` | 输出 OK（不弹密码） |
| 5 | SSH 密钥免密登录 | `ssh -o BatchMode=yes user@<VM_IP> echo OK` | 输出 OK（不弹密码） |
| 6 | 基线快照是否打过 | VMware 快照管理器 | 有 `baseline-<日期>` |
| 7 | 虚拟磁盘水位 | `df -h` | 使用率 < 70% |
| 8 | 系统时间同步 | `timedatectl` | 显示 sync 正常 |
| 9 | **VM 能否上网**（全部阶段的隐性前提） | VM 里 `ping -c3 223.5.5.5` + `ping -c3 www.baidu.com` | 外网 IP 和域名都通 |

**vibe 启动指令**：
> 「帮我做环境体检：检查我的 Ubuntu24 VM 当前状态，按上面 9 项逐项报告结论。没配的项，先给配置方案（含回滚），我确认后你执行。全程每步解释为什么。」

**通过标准**：9 项全部合格，VM 有静态 IP + 免密 SSH + 免密 sudo + 基线快照 + 能上网。从此"防兜圈"第一道墙就砌好了。

### 第一阶段：Linux 地基（2–3 周）
- **目标**：能独立 SSH 登录，看懂文件系统/权限/进程，敢改配置不怕坏。
- **关键内容**：SSH 登录与密钥、目录结构（/etc、/var、/usr…）、权限（chmod/chown/sudo）、用户与组、进程与 systemd 基础（**自己写一个 .service 单元文件并调试**）、apt 包管理、journalctl 日志、**Git 基础（从第一天用 Git 记录实验笔记，养成习惯）**。
- **逻辑关系**：这是"语言"，后面所有阶段都在说这门语言。
- **痛点难点**：权限计算（4-2-1）是第一个大坑；systemd 概念抽象；改配置手抖改坏系统（**先快照**）。
- **验收**：不用查资料用 SSH 密钥登录；看懂一条服务自启配置；能自己重装一个出错的包。
- **vibe 启动指令**：「今天学 Linux 地基第 1 课。用大白话讲 Linux 目录结构 + rwx 权限怎么算，举我们 VM 里的真实例子。给我 3 个由易到难的练习，我做完你检查并解释。今天只讲这块，别讲别的。」

### 第二阶段：系统管理（2–3 周）
- **目标**：把一台机器"管明白"——磁盘、用户、定时任务、资源，出问题能定位。
- **关键内容**：磁盘分区与挂载（lsblk/fdisk/fstab）、LVM（进阶）、cron 与 systemd timer、资源监控（top/free/df）、日志分析、软件源与升级策略、chrony 时间同步。
- **逻辑关系**：第一阶段"看得懂"，这阶段"管得住"；不学它后面做监控没有"基线"可对比。
- **痛点难点**：**磁盘满是最常见事故**（还有 inode、文件句柄两个隐藏坑）；fstab 写错开不了机（**靠快照兜底**）；监控命令要懂"数字代表什么"而非背命令。
- **验收**：能给新机器规划分区；设定时任务并验证；能定位"磁盘 90% 是哪个进程在写"。
- **vibe 启动指令**：「今天学磁盘管理。先讲 fstab 每列什么意思，然后设计一个"故意写错 fstab"的练习：我打快照 → 你指挥我弄坏 → 教我从 VMware 控制台救回来。目标是学会 fstab 写错开不了机怎么救。每步解释。」

### 第三阶段：网络服务（3–4 周）
- **目标**：会部署并排查最常见网络服务，理解"IP / 端口 / 域名"三角。
- **关键内容**：IP/掩码/网关/NAT/DNS 原理、**子网划分手算练习（CIDR，必练，面试常考）**、防火墙（**ufw 为主落地，iptables 只学概念不深挖**）、nginx 反代、SSH 隧道与跳板、排错工具（ping/traceroute/ss/curl）。
- **逻辑关系**：运维一半工作是"服务连不上"；同时练 SSH 跳板/隧道，是第一个实战分水岭。
- **痛点难点**：**排错顺序乱**（正确：自己→网关→DNS→端口→应用）；NAT/防火墙原理抽象；分不清 `Connection refused` 和 `Service Unavailable`（不同的故障层）。
- **验收**：从 Windows 用 SSH 隧道访问 VM 内部服务；自己写一条 ufw 规则并讲清；按顺序排查一次"nginx 连不上"。
- **vibe 启动指令**：「今天练网络排错。你在 VM 上故意搞出一个"服务连不上"的故障（防火墙挡或端口没监听），别告诉我原因，让我用分层定位法自己查出来。你只回答对/不对，我卡 10 分钟再提示。」

### 阶段 3.5：多机环境搭建课（3–5 天）——从 1 台到 3 台

阶段 5 需要多台机器，但"克隆 + 双网段 + 静态 IP + 免密"本身是独立技能，必须单独学。目标是搭出"node1 网关 + node2 负载均衡 + node3 控制端/监控"最小多机拓扑。

**关键内容**：
1. VMware 克隆（链接克隆 vs 完整克隆），克隆后**必改三件**：主机名、SSH host key、固定 IP。
2. 建 VMnet2 内网段（自定义网络，**无 DHCP，必须手配静态 IP**）。
3. node1 双网卡：外网接 VMnet8，内网接 VMnet2，做 NAT 网关（`net.ipv4.ip_forward=1` + 防火墙 MASQUERADE；**理解 nftables/iptables 概念即可，落地用 ufw/nft**）。
4. 控制端 → 各节点 SSH 免密打通。
5. 验证：内网机器能出外网、控制端能免密管理所有节点。

**逻辑关系**：这是"单机思维"到"多机思维"的转折点。搭完这套，阶段 5 的 Ansible 才有落点。

**痛点难点**：
- **VMnet2 没 DHCP**：克隆的机器不手配静态 IP，全部没内网 IP（最常见翻车点）。
- 网卡名克隆后变（ens33→ens37），netplan 配置对不上。
- 网关配了但内网出不去 = 忘了 `ip_forward` 或防火墙挡 FORWARD。

**验收**：从 node3 能免密 SSH 到所有节点；内网机器能 ping 通外网；node2 的 nginx 能被 node3 curl 到。

**vibe 启动指令**：
> 「今天搭多机环境：从我的 Ubuntu24 克隆 node1（双网卡网关）、node2（nginx）、node3（控制端）。按顺序：1) 建 VMnet2 内网段 2) 克隆并改主机名/IP/SSH host key 3) node1 配 NAT 网关 4) 控制端到各节点 SSH 免密。每步先讲做什么、为什么，我确认后执行，执行完验证连通性。」

### 第四阶段：Shell 自动化（3–4 周）——第一个分水岭
- **目标**：从"手动敲"升级到"写脚本批量干"。从"使用"到"工程"的质变。
- **关键内容**：bash 基础（变量/条件/循环/函数）、管道与三剑客（grep/awk/sed）+ **jq（JSON 处理，配合 curl 调 API，现代必备）**、**Git 正式课（分支/合并/回滚）**、退出码与 `set -e`、脚本参数、日志轮转。
- **逻辑关系**：前面所有命令是"积木"，脚本是搭出来的东西。**不学它，下一阶段 Ansible 只能看懂不能写**。
- **痛点难点**：引号/空格/通配符的坑（文件名带空格脚本就炸）；退出码思维（"看起来成功实际失败"）；awk/sed 语法反人类（靠查+反复用，别背）。
- **验收**：写自动备份脚本（保留最近 7 份、带错误处理）；用循环批量改 10 个文件。
- **vibe 启动指令**：「今天写第一个正式脚本：自动备份指定目录、保留最近 7 份、带错误处理。先给我设计思路（不写代码），我确认逻辑后你一句一句教我写。写完一起测一个错误场景（目录不存在）。每行讲为什么。」

### 第五阶段：Ansible + 监控（4–6 周）——第二个分水岭，SRE 门槛
- **目标**：用 Ansible 管多台机器（配置即代码），用 Prometheus 看监控，理解"声明式 vs 命令式"。
- **关键内容**：Ansible 架构（控制端/被管端/inventory）、playbook 与 role、**幂等性**、Prometheus + Node Exporter + **Alertmanager（告警通知引擎，缺它告警只是屏幕上的字）** + Grafana、告警规则；**进阶：OpenTofu（IaC 建资源）入门 + Python 基础（自动化天花板）**。
- **逻辑关系**：需克隆 2–3 台 VM，第一次把"自动化 + 配置管理 + 监控"串成闭环。这是"运维"和"SRE"的分界线。
- **痛点难点**：**幂等性思维**是编程思维分水岭；SSH 免密 + become 权限链路全是坑；Prometheus 概念多（**先跑通"采集→出图"闭环**再谈别的）；告警"狼来了"（先学会定合理阈值）。
- **验收**：Ansible 一条命令给 3 台装好 nginx 且幂等；Prometheus 监控所有机器，宕一台能看到告警。
- **vibe 启动指令**：「今天搭监控闭环：用 Ansible 给 3 台装 node_exporter，再部署 Prometheus + Grafana。先给方案（含回滚）→ 我确认 → 执行并逐步解释。目标理解"幂等性"和"采集→出图"闭环。每装一个组件暂停考我一句它在这干什么。」

### 第六阶段：容器与云原生（4–6 周）
- **目标**：懂 Docker 和轻量 k8s，理解"应用怎么打包、怎么被调度"。
- **关键内容**：Docker（镜像/容器/网络/数据卷/Dockerfile，用 `docker compose` 插件）、**Helm（k8s 包管理，部署软件的标准方式）**、k3s 核心概念（Pod/Deployment/Service/Ingress）、HPA/KEDA 弹性伸缩、**GitOps 入门（Argo CD：集群状态声明在 Git，自动同步）**。
- **前置配置**：Docker 镜像加速（阿里云/中科大加速器）+ k3s 国内安装源——`docker pull` 与 github 脚本在国内会慢/被墙，**先配再动手**，否则一整天卡在拉镜像。
- **逻辑关系**：容器是"标准化的运行层"，k8s 是"容器的操作系统"。现代云运维全在这个栈上。
- **痛点难点**：容器网络隔离 / 数据卷持久化（"容器一删数据没了"）；k8s 概念爆炸（**别从头学概念**，先跑最小案例再反推）；资源不够（用 k3s + 轻量配置，按需开 3 台）。
- **验收**：把一个应用打成镜像跑起来；在 k3s 上部署一个服务，滚动更新不中断；配一个 HPA 随负载伸缩。
- **vibe 启动指令**：「今天把 web 服务容器化并部署到 k3s：1) Dockerfile 打镜像 2) docker compose 本地跑通 3) 部署到 k3s（Deployment+Service）4) 配 HPA 用 k6 压测看自动扩容。每步先解释概念（k8s 用类比：Pod=房间，Service=门牌号）再执行。」

### 第七阶段：高可用 / 安全 / SRE（3 个月以上，长期）
- **目标**：从"能管几台"到"能设计不宕机的架构、能扛事故"。
- **关键内容**：负载均衡（nginx/HAProxy）、MySQL 主从与备份恢复（PITR）、故障演练（混沌工程入门）、安全加固（SSH 加固/最小权限/免密）、日志收集（**Loki + Promtail，明确不跑 ELK**）、**OpenTelemetry 概念（2026 观测标准，指标/日志/链路三合一，见第十二节）**、**eBPF 观测入门（Falco/Cilium 了解，不动代码看内核）**、**AI 辅助运维（Agentic SRE：用 AI 做根因分析与事故复盘，你负责定护栏与审核）**、SRE 方法论（SLI/SLO/容量规划/on-call）。
- **逻辑关系**：前六阶段是"会做"，这阶段是"扛得住"，回答终极问题：**系统坏了多久知道？多久修好？下次怎么不坏？**
- **痛点难点**：主从复制、备份恢复是硬功夫（**很多人从没真正恢复过一次**）；高可用是"贵+复杂"的艺术（VM 内存不够就一主一备）；SRE 方法论靠**事故复盘习惯**养成。
- **验收**：MySQL 主从故障 10 分钟内恢复；对拓扑做一次"杀节点演练"并写总结；给自己环境出一份安全加固清单并落实。
- **vibe 启动指令**：「今天做第一次故障演练（MySQL 主从）。先给完整方案（含回滚和恢复路径）→ 我确认 → 1) 搭主从 2) 打快照 3) 指挥我手动 kill 主库，计时看能否 10 分钟恢复 4) 一起写复盘（问题→原因→解决）。按"先方案后执行"。」

## 六、网络问题排查预案（重点）

### 6.1 排错心法：分层定位法

```
① 自己层   网卡有 IP 吗？接口 up 吗？          → ip a
② 链路层   ping 得通网关吗？                   → ip route / ping 网关
③ 网络层   ping 得通外网 IP 吗？               → ping 223.5.5.5
④ DNS      域名能解析吗？                      → ping 域名 / resolvectl query
⑤ 端口/应用 目标端口在听吗？防火墙挡了吗？      → ss -tlnp / curl / ufw status
```

**一步定位口诀**：
| 现象 | 结论 |
|---|---|
| 能 ping 通 IP，不能 ping 通域名 | **DNS 问题** |
| 内网通，外网不通 | **网关 / 路由 / NAT 问题** |
| 别人能通，只有自己不通 | **防火墙 / 端口 / 服务没起** |
| 网络全通，服务还是怪 | **大概率不是网络**，查磁盘/内存/时间 |

**8 步自查清单**：
```bash
ip a                 # 1.有IP吗？接口up吗？
ip route             # 2.默认网关在吗？
ping -c3 <网关IP>     # 3.内网通吗？
ping -c3 223.5.5.5   # 4.外网IP通吗？
ping -c3 www.baidu.com  # 5.域名通吗？
ss -tlnp             # 6.目标端口在听吗？
curl -v http://127.0.0.1:<端口>  # 7.本机能访问吗？
sudo ufw status      # 8.防火墙挡了吗？
```

### 6.2 各类问题与解决方案

**VMware 虚拟网络层**（最容易被忽略）：
| 问题 | 原因 | 排查与解决 |
|---|---|---|
| VM 里没有 IP（只有 lo） | VMware NAT/DHCP 服务没启动（Windows 更新后常停） | `services.msc` 里把 **VMware NAT Service** 和 **VMware DHCP Service** 设为自动并启动 |
| VM 能拿 IP 但上不了网 | NAT 网关/DNS 配置问题 | `ip route`（网关应是 192.168.x.x）；`resolvectl status` 看 DNS |
| 忘了 VM 的 IP | 忘了或 DHCP 变了 | VM 里 `ip a`；本机 `arp -a` 看 VMnet8 段 |
| VM 报虚拟化错误/卡 | BIOS 里 SVM/VT 没开 | 任务管理器→性能→CPU→虚拟化；进 BIOS 开 |
| 网卡 link down | 网卡没连上 | VM 设置勾"已连接"；`ip link set <网卡> up` |

**本机 ↔ VM（SSH 连接层）**：
| 问题 | 原因 | 排查与解决 |
|---|---|---|
| SSH 连不上 | 多层可能 | `ping <VM_IP>` → `Test-NetConnection <VM_IP> -Port 22` → `ssh -v` |
| "REMOTE HOST IDENTIFICATION HAS CHANGED" | 克隆/重装后 host key 变了 | `ssh-keygen -R <IP>` 再重连（克隆后必碰） |
| 克隆后两台 SSHD 证书一样 | 克隆把 host key 复制了 | `rm /etc/ssh/ssh_host_* && ssh-keygen -A` |
| SSH 连上就断/卡 Password | sshd 配置改了没生效或改坏 | 改配置先 `sshd -t` 验证再重启；**开两个会话** |
| Permission denied (publickey) | 密钥权限不对 | `chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys`；用 `ssh-copy-id` |

**VM 内网络服务层**：
| 问题 | 原因 | 排查与解决 |
|---|---|---|
| 开防火墙瞬间 SSH 断（经典翻车） | `ufw enable` 前没放行 22 | 先 `ufw allow OpenSSH` 再 `ufw enable`；断了用 VMware 控制台兜底 |
| 服务能起，外面访问不到 | 防火墙挡 / 只监听 127.0.0.1 | `ss -tlnp` 看监听地址；`ufw status`；nginx 监听 0.0.0.0 |
| nginx 起不来报端口被占 | 80 端口被占 | `ss -tlnp \| grep :80` |
| 改 netplan 直接断网 | `netplan apply` 立即生效 | 用 `netplan try`（120 秒自动回滚）；凉了就 VMware 控制台改回 |
| apt update 慢或报错 | 官方源在国外 | 换清华/阿里源。**Ubuntu 24.04 源文件是 `/etc/apt/sources.list.d/ubuntu.sources`** |
| curl 域名超时 | 机器挂了代理，VM NAT 跟着走 | `env \| grep -i proxy` 检查 |

**多机拓扑层**（第三阶段以后）：
| 问题 | 原因 | 排查与解决 |
|---|---|---|
| 克隆 5 台全没内网 IP | **VMnet2 默认没有 DHCP**，必须手动静态 IP | 每台手写静态 IP + 掩码 + 网关指向 node1 内网网卡 |
| 两台 IP 冲突，时而能连不能 | 克隆后没改静态 IP | 改静态 IP 后 `arping`/`ping` 验证唯一 |
| 内网能 ping 通网关但出不了外网 | node1 没开 IP 转发 | `sysctl net.ipv4.ip_forward=1` 写进 `/etc/sysctl.d/`；iptables `POSTROUTING MASQUERADE` |
| node1 开 ufw 后内网全断 | ufw 默认挡 FORWARD 链 | 网关这台别开 ufw，或单独放行转发 |
| 克隆后网卡名变了（ens33→ens37） | 可预测网卡名 + 克隆改 MAC | `ip link` 看新名字，改 netplan 配置（或按 MAC 匹配），`netplan try` |
| 外网访问不到内网服务 | **NAT 默认只出不进**（特性，非故障） | 需在 Virtual Network Editor 配端口映射 |

**中文 Windows 特有坑**：
| 问题 | 原因 | 解决 |
|---|---|---|
| 终端中文乱码 | Windows 默认 GBK，Linux 是 UTF-8 | 用 Windows Terminal；cmd 先 `chcp 65001` |
| 中文文件名在 bash 显示奇怪 | 编码 + 转义 | 服务器上统一英文命名 |
| VM 网络莫名挂了 | 360/腾讯管家拦 VMware 服务 | 加白名单；学习期用 Windows Defender 够用 |

**伪装成网络问题的非网络问题**（最坑，先查这三个）：
| 假象 | 真凶 | 一分钟验证 |
|---|---|---|
| SSH 连不上/服务起不来/各种怪错 | **磁盘满了** | `df -h`（也看 `df -i`） |
| 连接被重置/进程莫名消失 | **内存不足被 OOM** | `free -h` |
| SSH/HTTPS/Ansible 证书或握手错 | **时间不同步** | `timedatectl`，配 chrony |

**一句话速查表**：
> **连不上** → ping IP → ping 网关 → ping 外网 → ping 域名 → ss 端口 → ufw → 还不行就去查磁盘/内存/时间。
> **克隆后必改** → 主机名 + SSH host key + 静态 IP（三个一起）。
> **改网络配置必用** `netplan try`，**开防火墙先放行 SSH**，**动服务器前打快照**。

## 七、防兜圈协议（安全/权限/交互操作约定）

### 7.1 为什么会"兜圈"（原因分析）
| # | 原因 | 一句话解释 |
|---|---|---|
| 1 | 交互式命令挂起（最耗时） | `sudo` 要密码、`ssh` 要指纹确认、交互问答——Claude 非交互，**等不到输入 → 卡死 → 兜圈** |
| 2 | 权限/沙箱拦截 | sudo、改网络、装系统包被拦，换写法重试，又几轮 |
| 3 | 模型安全偏好回避 | 危险操作被保守对待：解释风险→给替代→要确认→不干脆执行 |
| 4 | 环境没配"提权通道" | 没配免密 sudo、SSH 免密、known_hosts 预填——**每个操作卡一次交互** |
| 5 | 流程问题 | 报错就地猜，不收集信息，来回试错 |

> 结论：80% 是流程卡壳（非交互环境撞上交互命令），20% 才是真安全。预案目标是消掉 80%，把 20% 改成"一次性确认"。

### 7.2 四条铁律

**第一步：一次性前置配置（30 分钟，省几个月）**
1. VM 配免密 sudo（用户加 `NOPASSWD`）。
2. 打通 SSH 免密（本机→node1→各节点），`known_hosts` 用 `accept-new` 预填。
3. Claude Code 常规运维命令加权限白名单；破坏性命令保留确认。
4. 打一个"干净基线"快照，所有实验从这出发。

**第二步：协作约定**
1. 安全相关任务**先出预案再执行**：方案 + 回滚 + 需批准点，**一次性确认**，确认后不再中途反复问。
2. **能非交互就非交互**：免密、`ssh -o BatchMode`、参数化命令、改配置文件代替交互工具；真需要人手的**明确说"这步请你在终端手动跑"**并给完整命令。
3. 执行边界写死：常规直接干（查看/安装/改配置）；高危必须先问（防火墙全局改动、iptables 清空、删数据、关安全功能）。边界内绝不啰嗦。

**第三步：两个 vibe 授权模板**
> 批量授权：以下操作都在我的实验 VM 上，已打快照：`<操作清单>`。授权你直接执行，不用逐条确认，但每步仍要解释为什么。只有遇到"会破坏系统且无法回滚"的风险时，停下来说明理由。
> 高危任务：这个任务涉及安全加固：先给我完整方案（含回滚），我确认后你一次性执行完，中途不要反复问我。

**第四步：失败快速升级机制（3 次规则）**
- 失败 1 次：Claude 自己看报错解决，不打扰用户。
- 失败 2 次：**立即停止猜测**，不换命令硬试。让用户贴「三件套」：报错原文 + 相关配置 + 当前环境状态。
- 失败 3 次：降级半自动——Claude 给每步命令和原因，用户在终端手动跑、贴回输出；或换思路换工具，不原地打转。

### 7.3 落实到你后面的具体任务
| 任务 | 会踩的"安全问题" | 预案 |
|---|---|---|
| node1 上 ufw/iptables | 防火墙高危被拦 + 反复确认 | 列入高危清单：先出方案含回滚，一次性授权 |
| Ansible 里 sudo | 密码交互卡死 | 配 NOPASSWD + `become` 免密 |
| 磁盘分区 / mkfs | 破坏性操作被拦 | 快照兜底 + 一次性确认 |
| SSH 加固 | 改坏配置直接断连 | `sshd -t` 先验 + 双会话保底 |
| 装 fail2ban 等常规包 | 权限提示刷屏 | 白名单直接过 |

### 7.4 诚实边界
真危险的（清空防火墙、删数据、关安全功能、对外部机器攻击性操作）**该确认还是要确认**——这是原则。但确认改成"一次问清、不绕"：给完整方案和理由，用户一句话放行。

## 八、代理（PandaFan）操作协议

**本机代理** = PandaFan（Electron 壳 + **Clash 内核**），用户数据在 `C:\Users\<USER>\AppData\Roaming\PandaFan\`。

| 项 | 值 |
|---|---|
| HTTP+SOCKS5 混合端口 | **10080** |
| SOCKS5 端口 | 10081 |
| 管理 API | 127.0.0.1:10079 |
| 模式 | Rule（规则分流） |

**判断代理是否可用**（用前必查）：
```bash
netstat -ano | grep 10080   # 有 LISTENING = 代理可用
```

**走代理命令前缀**（代理开着时）：
```bash
export https_proxy=http://127.0.0.1:10080 http_proxy=http://127.0.0.1:10080 all_proxy=socks5://127.0.0.1:10081
```

**操作约定**：
1. 遇到网络问题需要代理时，**直接报告**：什么问题、为什么需要代理、代理当前是开是关。
2. 代理开着 → 直接用 10080 前缀。
3. 代理关着 → 报告"代理未启动，需要用户在 PandaFan 里点连接"，**不擅自拉起 clash 进程**（避免双实例打架）。
4. 已知状态（2026-08-01 实测）：GUI 在跑，但 clash 内核未启动（10080 无监听）。
5. **运维实验时系统代理保持 OFF**：系统代理一开，可能影响 Claude 自己的联网调用，也可能影响 VM 走 NAT 的流量。做实验前先确认代理已关；确需走代理（拉国外资源）单独开、用完即关。

## 十二、2026 前沿动向与技术融入（实时雷达，2026-08 核实）

> 以下均为 2026 当下已确认的真实状态（非预测）。原则：**方向性知识入课，工具性名词了解即可，别追名词跑。**

### 1. Agentic SRE / AI 辅助运维 —— 行业最大方向，本计划已按此设计 ⭐
- Gartner 2026 预测：2029 年 **85% 企业将使用 AI SRE 工具**（2025 年还不到 5%）。AI 已能做根因分析、事故总结、告警降噪（"70% 告警不可用"是行业老大难）。
- **关键不是模型多聪明，是"护栏 + 可信"**：权限模型、审批门、审计、回滚、渐进式自治（先从"只读诊断"到"低风险自动化"）。
- **这正好就是你本计划的"防兜圈协议"**——人定护栏、AI 执行、先方案后执行、失败分级升级。你学的不是"被 AI 取代"，是"如何给 AI 定规矩、审 AI 的活"。这是 2026 运维人的新核心技能，你从第一天就在练。
- 落点：阶段 7 专练"AI 辅助故障复盘"，其余阶段延续 vibe 工作法。

### 2. OpenTofu —— 开源 IaC 的默认选项（Terraform 已转向商业）
- 2023 年 HashiCorp 把 Terraform 改为商用许可证（BSL）后社区分叉出 **OpenTofu**；2025 年入 CNCF，2026 年成为开源默认（HCP Terraform 免费层 2026 年 3 月取消；IBM 收购 HashiCorp 后路线图由厂商掌控）。
- 语法与 Terraform 完全兼容（都是 HCL），迁移=换二进制。**学 IaC 从 OpenTofu 入门，以后接触 Terraform 无缝切换。**
- 落点：阶段 5 进阶项即为 OpenTofu。

### 3. OpenTelemetry（OTel）—— 2026 观测事实标准（已从 CNCF 毕业）
- 2026 年 5 月 OTel 从 CNCF 毕业，**78% 企业生产在用**。它统一指标/日志/链路三种数据，解决"换监控厂商就要重写全部埋点"的锁死问题。
- 落点：阶段 7 只学"一个概念 + 一个 Demo"：知道 OTel Collector 怎么收三种数据、为什么它是标准。你的 Prometheus/Loki 照用，但认知上要理解 OTel 是"前端采集统一、后端随便接"。

### 4. GitOps —— 声明式运维的标配（Argo CD / Flux）
- k8s 时代部署主流 = 把集群期望状态声明在 Git 仓库，Argo CD 自动同步。2026 已是成熟标配。
- 落点：阶段 6 加 Argo CD 最小案例（k3s 上部署，从 Git 仓库拉配置自动同步）。

### 5. eBPF 观测/安全 —— 内核级新一代观测
- Cilium（网络/安全）、Falco（运行时安全）、Tetragon、Grafana Beyla 等，**不改应用代码**就能看到内核层行为。
- 落点：阶段 7 概念了解 + 装一个 Falco 看效果，理解"不动代码也能观测"的思路。

### 6. 供应链安全（SBOM / SLSA）
- 软件供应链攻击是主流攻击面，**SBOM（软件物料清单）** 成为合规要求。
- 落点：阶段 7 一笔带过——知道"镜像要签名、物料要清单"即可。

### 7. 其它趋势（纯雷达，不入课）
- **Platform Engineering（平台工程）**：大厂把"铺路"做成产品（Backstage 等），是运维的高阶职业方向。
- **Serverless / FinOps / Edge**：云资源成本治理与边缘计算，进阶再看。
- **结论**：第 1–4 条是你"专家期"前就该碰的方向性知识；第 5–7 条了解即可。
