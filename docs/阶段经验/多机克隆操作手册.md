# 多机克隆操作手册（node 拓扑搭建）

> 用途：从模板机克隆多台 node、配双网段拓扑。照着做，不返工。
> 适用：阶段 3.5 及以后所有"克隆多台"的需求（Ansible、k8s 都要复用）。
> 踩坑教训已固化：**改 IP 前先看网卡名、apply 后等 10 秒连新 IP、NAT 规则要持久化**。

---

## 〇、三条铁律（这次最痛的教训，先背）

1. **改 IP/网段前，先 `ip a` 看实际网卡名**（别猜 enp0s17/18，克隆后网卡名会变）。
2. **`netplan apply` 后 SSH 必然断、IP 切换有延迟**——apply 后等 10 秒，直接连**新 IP**，别回头试旧 IP。
3. **改防火墙/NAT 规则必须持久化**（iptables 规则重启即失）。

---

## 一、前置准备（动手前确认）

| 项 | 要求 | 检查命令 |
|---|---|---|
| 模板机 | 干净基线（至少没有业务软件） | 启动后 `which nginx` 应为空 |
| 模板机快照 | 有 L0/L1 快照，克隆源从快照 | `vmrun listSnapshots` |
| 模板机状态 | **关机**（从快照克隆必须关机） | `vmrun list` 应为 0 |
| D 盘空间 | 每台完整克隆约 4-8G | `df -h /d` |
| 宿主内存 | 每台 2G，三台同时 6G，**按需开机** | `free` 空闲 ≥4G |
| 目标 IP 规划 | 先写死：每台主机名/IP/角色 | 一张表（见下） |

**IP 规划表模板**（十位递增，主机名带角色+末字节）：

| 机器 | 主机名 | 外网IP | 内网IP | 角色 |
|---|---|---|---|---|
| 网关 | node1-gw-20 | 192.168.x.x | 192.168.x.x | 网关+防火墙 |
| 负载均衡 | node2-lb-30 | 192.168.x.x | — | nginx |
| 控制端 | node3-ctl-40 | — | 192.168.x.x | Ansible/监控 |

## 二、克隆（两种方式，GUI 最稳）

### 方式 A：GUI 克隆（推荐，最稳）
1. VMware → 右键模板机 → **Manage → Clone**
2. **注意选快照源**：对话框里选"从快照"而不是"当前状态"（当前状态=脏）
3. 克隆到 `D:\VM\nodeX\`，命名 `nodeX.vmx`

> GUI 克隆完如果 MAC 没重新生成（vmx 里 generatedAddress 和模板一样），**两台同网段会 IP 冲突**——克隆后在 vmx 里确认 MAC 不同。

### 方式 B：vmrun 命令行克隆
```bash
# 模板机必须关机！
"/c/Program Files (x86)/VMware/VMware Workstation/vmrun.exe" -T ws clone "D:/VM/模板机.vmx" "D:/VM/nodeX/nodeX.vmx" full
```
> ⚠️ 此环境的 vmrun 与 GUI 可能不同步（list 报 0 但实际在跑），**失败 2 次立即转 GUI**，别死磕。

## 三、每台必做的"三件套"（克隆后）

> 三台都做，顺序固定。**一次只开一台**，配完关机再开下一台（防内存爆 + 防 IP 冲突）。

### 第 1 步：启动并找到临时 IP
```bash
vmrun start "D:/VM/nodeX/nodeX.vmx" nogui
sleep 45
# 找到它的临时 IP（DHCP 可能拿 .10 或别的）
arp -a | grep 192.168.56
# 扫描 22 端口确认
for i in 10 11 12; do timeout 2 bash -c "echo >/dev/tcp/192.168.x.x$i/22" 2>/dev/null && echo ".$i 通"; done
```

### 第 2 步：SSH 进去改三件套（一次性脚本）
```bash
ssh-keygen -R <临时IP>   # 清旧 host key（克隆机 MAC 变了，key 会变）
ssh user@<临时IP> "sudo -n bash -c '
set -e
echo <主机名> > /etc/hostname
sed -i \"s/^127.0.1.1.*/127.0.1.1 <主机名>/\" /etc/hosts
rm -f /etc/ssh/ssh_host_*
ssh-keygen -A >/dev/null 2>&1
cat > /etc/netplan/50-cloud-init.yaml <<EOF
network:
  version: 2
  ethernets:
    <实际网卡名>:
      dhcp4: false
      addresses:
        - <目标IP>/24
      routes:
        - to: default
          via: 192.168.x.x
      nameservers:
        addresses:
          - 223.5.5.5
          - 127.0.0.53
EOF
hostname <主机名>
echo CONFIG_DONE
'"
```

> **关键**：`<实际网卡名>` 必须先用 `ip a` 确认，别照抄 enp0s17。克隆后可能变。

### 第 3 步：应用 IP（apply 后等 10 秒连新 IP）
```bash
ssh user@<临时IP> "sudo netplan apply"   # SSH 会断，正常
sleep 10
ssh-keygen -R <目标IP>
ssh user@<目标IP> 'hostname; ip -4 a | grep inet'   # 连新 IP 验证
```

### 第 4 步：清理模板残留（每台）
```bash
crontab -r                     # 清隧道自启（以 pc 用户身份跑，不是 sudo）
sudo rm -rf ~/.tunnel   # 删隧道脚本
```

## 四、node1 网关特配（只有网关需要）

### 1. 加第二块网卡（VMnet2）
- GUI：node1 设置 → 添加网络适配器 → 自定义 → VMnet2
- 或改 vmx 追加：
  ```
  ethernet1.present = "TRUE"
  ethernet1.connectionType = "custom"
  ethernet1.virtualDev = "e1000"
  ethernet1.vnet = "VMnet2"
  ```

### 2. 重启后配内网口 + 转发 + NAT
```bash
ssh user@node1 "sudo bash -c '
# 先看第二块网卡名
ip a
# 加内网 IP（假设 enp0s18）
echo net.ipv4.ip_forward=1 > /etc/sysctl.d/99-forward.conf
sysctl -p
# NAT 规则 + 持久化（防重启丢失！）
iptables -t nat -A POSTROUTING -s 192.168.x.x/24 -o <外网网卡> -j MASQUERADE
mkdir -p /etc/iptables && iptables-save > /etc/iptables/rules.v4
# netplan 加内网口
'"
```

> **NAT 规则持久化**是 node1 踩过的大坑——`iptables-save > /etc/iptables/rules.v4` 必须有，否则重启后内网出不了外网。

## 五、node3 挪进内网（控制端特配）

1. **先确认网卡名**：`ip a` 看实际网卡（别猜）
2. 改 vmx 网卡 → VMnet2
3. **临时加一块 VMnet8 网卡**（否则 SSH 连不上，配不了）
4. 控制台/SSH 配 netplan：
   ```
   <内网网卡>: 192.168.x.x/24
   默认网关: via 192.168.x.x (node1 内网口)
   ```
5. 验证：`ping 192.168.56.20`（内网通）→ `ping 223.5.5.5`（出外网）

## 七、这次踩的坑速查（下次遇到直接翻）

| 现象 | 原因 | 解法 |
|---|---|---|
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | 克隆后 host key 变了 | `ssh-keygen -R <IP>` 重连 |
| apply 后 SSH 断、旧 IP 不通 | IP 切换中，正常 | 等 10 秒连新 IP |
| 两台同 IP 冲突 | 克隆后 MAC 没变 / 同时开两台 | 一次只开一台，配完再开下一台 |
| node3 网卡挪了 SSH 失联 | netplan 网卡名/网段对不上 | 控制台 `ip a` 看实际名，重配 netplan |
| 内网通、外网不通 | node1 NAT 规则丢了 | 补 MASQUERADE + `iptables-save` |
| vmrun 报"已在运行" | vmrun 与 GUI 不同步 | 转 GUI 操作，失败 2 次就切 |
