## 一·1、三台 node 详细描述（角色特征 + 所有修改）

### node1-gw-20 —— 网关 + 防火墙 + NAT

| 项 | 值 |
|---|---|
| vmx | `D:\VM\node1\node1.vmx` |
| 内存 | **1G**（从 2G 降到 1G，网关不吃内存） |
| CPU | 2 核 |
| 网卡 | **双网卡**：enp0s17 外网(VMnet8) / enp0s18 内网(VMnet2) |
| IP | 外 `192.168.x.x/24`、内 `192.168.x.x/24` |
| 角色 | 全拓扑的中枢：内网出外网靠它 NAT |

**做的所有修改**：
1. 三件套：主机名 node1-gw-20、重生成 SSH key、静态 IP .20
2. vmx 加第二块网卡 ethernet1 → VMnet2（内网口 enp0s18）
3. 开启转发：`net.ipv4.ip_forward=1`（/etc/sysctl.d/99-forward.conf）
4. NAT 伪装：`iptables -t nat POSTROUTING -s 192.168.x.x/24 -o enp0s17 MASQUERADE`
5. **NAT 持久化**：`iptables-save > /etc/iptables/rules.v4`（防重启丢失）

**特征**：全拓扑唯一有双网卡的机器，内网段机器的默认网关指向它的内网口（192.168.56.20）。

| 项 | 值 |
|---|---|
| vmx | `D:\VM\node3\node3.vmx` |

**做的所有修改**：

**特征**：唯一在内网段的机器，出外网走 node1 网关。将来是"指挥中心"。

## 二、本次完整操作链（按发生顺序）

### 1. 阶段 0 铺垫（早已完成）
静态 IP `.10`、NOPASSWD 免密 sudo、SSH 密钥免密、基线快照 `baseline-20260801`。

### 2. 评估与准备模板
- 检查宿主：15.3G 内存、空闲波动 3-4G、D盘充足、vmrun 可用
- 发现工作机已"脏"（装了 nginx/htop/隧道脚本），不能直接当模板
- 用户指定 `D:\VM\<template-vm>` 为模板机，从工作机快照克隆，体检基本干净

### 3. 克隆三台 node
- 用 vmrun clone 从模板克隆 node1/2/3（full 完整克隆）
- 失败记录：vmrun 一度报"虚拟机已在运行"（VMware GUI 与 vmrun 不同步）

### 4. 三台逐个配置"三件套"
主机名 + SSH host key + 静态 IP，一次一台，配完关机再开下一台。

### 5. node1 网关特配
- 加第二块网卡（改 vmx）→ enp0s18 内网口 192.168.56.20
- 开 ip_forward + 加 NAT（MASQUERADE）规则
- **坑**：重启后 NAT 规则丢失 → 补规则 + `iptables-save` 持久化

### 6. node3 挪进内网
- 改 vmx 网卡 → VMnet2
- 加临时 VMnet8 网卡保 SSH
- **坑**：netplan 网卡名/网段对不上，SSH 失联 → 用户进控制台手打 netplan 救回
- 配 192.168.56.40，网关 192.168.56.20

### 7. 验收
- node3 内网出外网 ✓（ping 223.5.5.5）
- node3 免密 SSH 到 node1/node2 ✓
- 双网段隔离 ✓

## 三、踩坑与教训（最重要，务必记住）

### 坑 1：模板机"干净"标准卡死进度
- **教训**：纠结"模板必须完美干净"导致反复折腾快照克隆。实际上"基本干净 + 克隆后清理"完全够用。**理想标准是方向，不是卡死进度的高墙**，该务实就务实。

### 坑 2：`netplan apply` 后 SSH 断 + IP 切换延迟，反复试旧 IP
- **教训**：改 IP 后 SSH **必然断**，切换有延迟。**正确动作：apply 后等 10 秒，直接连新 IP**，别回头试旧 IP。前三台第三台才掌握，浪费大量时间。

### 坑 3：vmrun 与 GUI 不同步，死磕命令行
- **教训**：vmrun 在此环境不稳定（list 报 0 但实际在跑、clone 报"已在运行"）。**失败 2 次立即转 GUI**，别死磕。工具不可靠时及时切换路径。

### 坑 4：网卡名/网段对不上，node3 失联
- **教训**：**改网卡/网段前，先 `ip a` 确认实际网卡名**（克隆后 ens33→ens37 会变）。文档 §6.2 明写，明知却没先做。

### 坑 5：NAT 规则没持久化
- **教训**：iptables 规则**重启即失**。改完必须 `iptables-save > /etc/iptables/rules.v4`，否则内网出不了外网。

### 坑 6：host key 冲突
- **教训**：克隆后 host key 变，SSH 报 `REMOTE HOST IDENTIFICATION HAS CHANGED` → `ssh-keygen -R <IP>` 清掉重连。多台轮流占同一 DHCP IP 时尤甚。

## 四、可复用操作（快速回忆）

**三件套**（每台克隆后必做）：
```bash
# 改主机名
echo <主机名> > /etc/hostname
sed -i "s/^127.0.1.1.*/127.0.1.1 <主机名>/" /etc/hosts
# 重生成 SSH host key
rm -f /etc/ssh/ssh_host_* && ssh-keygen -A
# 改静态 IP
cat > /etc/netplan/50-cloud-init.yaml <<EOF
network:
  version: 2
  ethernets:
    <实际网卡名>:
      dhcp4: false
      addresses: [<IP>/24]
      routes:
        - to: default
          via: <网关>
      nameservers: {addresses: [223.5.5.5]}
EOF
netplan apply
```

**node1 网关**：
```bash
# 加第二块网卡后（改 vmx），重启配：
echo net.ipv4.ip_forward=1 > /etc/sysctl.d/99-forward.conf && sysctl -p
iptables -t nat -A POSTROUTING -s 192.168.x.x/24 -o <外网网卡> -j MASQUERADE
iptables-save > /etc/iptables/rules.v4   # 持久化！
```

**node3 挪内网**：改 vmx 网卡→VMnet2，加临时 VMnet8 网卡保 SSH，netplan 配内网 IP+网关指向 node1。

## 五、内存与开机策略（重要）

- 宿主 16G 内存，三台 2G = 6G VM 内存，Windows 需留 3-4G
- **空闲 3-4G 是常态**，三台全开会紧张
- **平时按需开机**：学习哪台开哪台，不用全开
- 无头模式（nogui）省资源，需要看画面才用 GUI
