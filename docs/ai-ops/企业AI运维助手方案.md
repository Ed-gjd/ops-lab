# 某企业 AI 运维助手 · 企业级方案（课14 交付文档）

> 依据：本学习路线全链路实测数据（阶段C/D 资产）。撰写日：2026-08-05。
> 定位：一份可直接交付给技术评审会的方案文档——**选型有理由、成本有算式、安全有依据、风险有回滚**。

---

## 一、需求与目标

**业务痛点**：运维团队 5 人，日均处理查询类工单 40+（磁盘/服务/日志/告警判断），大量重复劳动，值班经验难沉淀。

**目标**：
1. 用 AI 助手承接 70% 查询类工单，把磁盘/服务/日志排查从"人工敲命令"变成"自然语言一问即答"
2. 值班经验固化成知识库（RAG），新人上岗时间从 2 周压到 3 天
3. **不碰生产写操作**——只读白名单，事故零容忍

**不做什么**（边界明确）：不自动执行变更（部署/删改/重启由人审批），不碰核心账务系统。

---

## 二、技术选型矩阵（有理由）

| 环节 | 选型 | 理由（实测依据） |
|---|---|---|
| 基座模型 | `qwen3.7-flash`（查询类）+ `qwen-plus`（复杂推理） | 实测 flash 比 plus 快 ~10 倍（1.45s vs 14.44s）、token 更省（862 vs 896），查询类答案质量足够 |
| 编排 | 高代码 + MCP（自研） | 要工具回环/白名单/错误回喂，零代码页给不了深度 |
| 工具层 | MCP（FastMCP 自建） | 标准协议，tools/list→call 全链路验证过 |
| 知识 | 托管 Knowledge Studio（生产）/ 本地 RAG（开发） | 生产要 Rerank/Agentic RAG/多模态，托管省运维；开发用自建省钱练原理 |
| 安全 | 白名单 + 危险符号正则 + kill switch + 日志脱敏 | 实测 10/10 攻击拦截；去白名单后拦截率掉到 5/10 |
| 评测 | eval_20（自建评测集） | 可重复跑，20 条=10 正常+10 红队，防改版退化 |

**为什么不用工作流**：运维查询流程不固定（用户问法千变），固定节点会漏场景；**为什么不用 max 模型**：成本 ×10 且查询类无收益。

## 三、成本测算（可对账的算式）

**基础假设**：日 40 工单 × 每单约 5 次模型调用 × 250 工作日。

| 项 | 单价（据百炼定价页，2026-08） | 月成本估算 |
|---|---|---|
| 模型调用（flash 为主） | 按 token（flash 最省） | 查询类约 ¥40-80/月（token 用量可在控制台对账） |
| 托管知识库 | 标准版 ~0.1-0.5 元/时 | 常开 ¥72-360/月 → **按需开**，或用本地 RAG 省掉 |
| LoRA 微调（可选） | 0.5-2 元/时 | 一次性几十元内 |
| Batch 批量评测 | 实时价 50% | 月评测成本可忽略 |
| Token Plan 个人版 | 39 元/月 | 开发者调试期推荐 |

**总账**：生产部署后月成本 **≈ ¥150-400**，对比省下 2 个人力（>¥2 万/月）——**ROI 明确**。
**预算护栏**：控制台设月度预算 + 用量统计盯数，超阈值自动告警。

## 四、部署模式三选（按企业规模）

| 模式 | 适用 | 成本 | 数据合规 |
|---|---|---|---|
| **公有云按 Token** | 中小团队、数据不敏感 | 最低（用多少付多少） | 数据出域，需脱敏 |
| **专属资源（PTU）** | 高并发/低延迟关键业务 | 中（按时长） | 资源独享 |
| **私有化部署** | 金融/政企，数据不出域 | 高（自建 GPU） | 完全可控 |

**本方案推荐**：先公有云按 Token 起步（1 个月试运行），指标达标后按需升级专属资源；金融场景直接私有化。

---

## 五、安全合规

- **权限最小化**：agent 只有只读白名单，无写/删/关权限（实测 `rm`/`shutdown`/`fdisk`/`sudo` 全拦）
- **OWASP ASI Top10 对齐**：ASI01 目标劫持→输入净化；ASI02 工具滥用→白名单；ASI06 记忆投毒→历史危险指令一律无效；ASI08 级联故障→`STATUS:` 语义化，下游禁止从错误串推结论
- **日志脱敏**：密钥/密码格式自动 `[MASKED]`（已修复尾巴泄露缺口）
- **合规**：凭证存 WSL2 0600 权限；控制台实名操作归管理员；敏感数据不进日志

## 六、评测指标（上线前的门禁）

| 维度 | 指标 | 门槛 |
|---|---|---|
| 可用性 | 查询成功率 | ≥ 90%（实测 100%） |
| 安全性 | 红队攻击拦截率 | **100% 硬性**（实测 10/10） |
| 性能 | 平均响应延迟 | < 5s（flash 实测 ~1.5s） |
| 成本 | 单工单 token | 设上限，超限降级模型 |

**门禁流程**：改版 → 跑 `eval_20.py` → 全绿才准上线 → 灰度 10% → 盯指标 → 放量或回滚。

---

## 七、上线应急（预案）

1. **版本化**：提示词/配置进 Git，改版有 diff 可回滚
2. **灰度**：新版本 10% 流量起步
3. **kill switch**：`OPS_GUARD_KILLED=1` 一键全停（已实现）
4. **回滚**：指标异常 10 分钟内回上一版本
5. **值班兜底**：agent 全停不影响人工通道（agent 是加速器，不是单点依赖）

---

## 八、风险与回滚

| 风险 | 概率 | 缓解 |
|---|---|---|
| 模型幻觉编造系统状态 | 中 | 只读工具 + 双层防幻觉（阈值+提示词），无命中必须明说 |
| 越权执行危险命令 | 低 | 白名单硬拦截 + 评测门禁 100% |
| 成本失控 | 低 | 预算护栏 + 用量统计 |
| 改版退化 | 中 | eval_20 回归门禁 |
| 知识库过期 | 高 | 定期更新 + 评测集随功能迭代维护 |

**回滚路径**：任何一环出问题 → kill switch 全停 → 回滚配置 → 人工值班接管。
